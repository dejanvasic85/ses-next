## Diagnosis log - the August click collapse

Work done 2026-09-10 and 2026-09-11 against issue #695. This section is the record of the month's
SEO work for invoicing, because the diagnosis ran through Search Console and curl
and left no commit trail of its own.

### What we set out to test

August's scorecard found clicks and phone leads falling while rankings held or
improved. The leading hypothesis was the design-system and nav rebuild (PR #648/#650,
30 July) and the services hub redesign (PR #671/#672, 8 August), both of which shipped
inside the measurement window. Issue #695 set two checks before any new content work:
are Google's snippets stale, and does the click-to-call event still fire.

### Check 1 - stale SERP snippets: ruled out

URL Inspection on `/locations/electrician-seddon` came back healthy. Last crawl
3 September, well after both rebuilds. Page fetch successful, page indexed, canonical
correct. A `site:sesmelbourne.com.au` search showed current, well-formed snippets
across the home, services, blog, FAQ and terms pages. Snippets are not the problem.

### Check 2 - the unstyled screenshot: a red herring, but it surfaced a real bug

The Inspection Tool's rendered screenshot showed the page completely unstyled: nav as
a bullet list, blue underlined link text, an unsized phone icon filling the viewport.

We first traced this to `robots.txt`, which carried `Disallow: /_next/` and so blocked
every stylesheet and script the site serves. That is a genuine problem and we fixed it
(PR #725), because Google cannot assess layout or mobile-friendliness on a page whose
CSS it is not allowed to fetch.

But it was not the cause of the unstyled screenshot. After the fix deployed, a fresh
Live Test rendered exactly the same way. Digging into the served CSS explains why:
the site is on Tailwind v4, and 95.7% of the stylesheet sits inside `@layer` blocks.
The Inspection Tool renders with an older Chromium than live Googlebot, and a renderer
without CSS cascade-layer support drops every layered rule, keeping only the 4.3%
remainder. That is precisely the page in the screenshot.

So the screenshot could not have looked any different, before or after the fix. It is a
limitation of the inspection renderer, not evidence about what live Googlebot sees.
Live Googlebot runs an evergreen Chromium that has supported cascade layers since
Chrome 99.

**Correction to our own reasoning:** we initially read the unstyled screenshot as proof
of a rendering failure and named the robots block as the leading cause of the August
collapse. That was overstated. The robots fix was still worth shipping on its own
merits, but it should not be treated as the explanation for the click drop, and the
August collapse remains unexplained.

Practical consequence: URL Inspection cannot verify rendering on this site. Use Search
Console's Core Web Vitals and Page Experience reports, which reflect real Chrome users,
or judge from impressions and positions directly.

### Check 3 - click-to-call markup: broken

The phone link renders as `href="tel:0415 338 040"` with raw spaces, where it should be
`tel:+61415338040`. This is a plausible cause of GA4 `first_time_phone_call` falling
from 23 in July to 2 in August.

### Also found

- The phone number in the Seddon page's meta description, (03) 4050 7937, does not match
  the 0415 338 040 in the page body. Karl is updating the content.
- The FAQ page's meta description double-escapes an ampersand. It reaches the live SERP
  as `solar &amp; more`.
